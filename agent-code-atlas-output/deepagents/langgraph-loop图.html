langgraph 引擎内部 · loop 怎么转

deepagents 把 agent loop 整体委托给它 —— 这张图就是"发动机"的缸内视角 · 依据 langgraphjs 审计数据绘制(Python 版同构)· 配套 report.html 与 钩子架构图 阅读
agent 节点(模型调用) tools 节点(工具执行) 超步(superstep) 引擎地盘(langgraph 内核)

一 · 最大反转:langgraph 也有 while,但转的不是"模型调用"

传统 agent loop 的伪代码是 while True: 调模型 → 有无工具调用? —— 循环一圈 = 问一次模型。 langgraph 的内核恰好反过来:外层是 while (await loop.tick(...))(PregelLoop,审计 loop.ts), 但循环的每一圈是一个 超步(superstep) = "一批被触发的节点并发执行一次"。是否继续不由模型输出决定,由"有没有节点被 channel 新版本触发"决定——模型调用只是恰好发生在某个节点里。

类比:电子表格。通道(channel)= 单元格,节点 = 公式。你改了一个格子(写入状态),引用它的公式自动重算——没有任何人在"while 循环里调用公式",是数据变化拉动计算。这就是比较报告说的"六家中唯一的数据驱动循环"。

二 · 引擎大循环:一个 tick 的四步(审计 loop.ts / Pregel._runLoop)

while (await loop.tick()) —— 每圈 = 一个超步
①收写回:把上一超步所有节点的产出,按各 channel 的 reducer(合并函数)写回通道 —— deepagents 的 DeltaChannel 就是在这里替换了 messages 通道的合并规则,把 checkpoint 从 O(N²) 压到 O(N)
▼
②存档:写 checkpoint(_putCheckpoint)—— 每个超步边界自动存一次,这就是 deepagents"断点恢复 / interrupt 后可 resume"的全部来源,没有任何中间件参与
▼
③调度:计算下一批任务(_prepareNextTasks)—— 扫一遍 channel 的新版本,被"新数据"触发的节点进入下一批;批内节点并发执行(配重试/超时/取消信号)
▼
④执行与检查:一批任务跑完,回到 ①。停止三途径:没节点被触发(自然终止)/ 步数超 recursionLimit(默认 25,deepagents 改 9999)抛 GraphRecursionError / interrupt() 暂停(可恢复)
tick 返回 false(无事可做)→ 循环退出 → 图执行结束
类比:施工队按节拍干活。每拍结束全员交活入库(①写回),仓管员拍快照存档(②),工头巡视哪些岗位的原料被更新了、点名下一拍上场的人(③),没活可派就收工(④)。Agent 节点和 tools 节点就是两个工种,互相交活,谁也不"调用"谁。

四 · 一次工具调用的超步走查(把两张图叠起来)

超步 0
用户消息写入 messages 通道
触发 agent 节点(它的触发条件 = messages 有新写入)
超步 1
agent 节点执行
tick ①收写回 → ②存档 → ③调度点名 agent → ④节点内部:中间件栈加工请求 → 调模型 → 返回 AIMessage(含 tool_calls:"search_web")。写回:AIMessage 追加进 messages 通道。
调度
条件边路由(不是循环,是路标)
路由函数读最新状态:最后一条消息带 tool_calls?是 → 下一超步触发 tools 节点
超步 2
tools 节点执行
ToolNode 分派 search_web → 执行(权限/落盘钩子在此)→ ToolMessage 写回 messages。固定边:tools 干完必回 agent。若此间调用 interrupt() → 整个超步暂停、checkpoint 持久化,等人 Command(resume)
超步 3
agent 节点再执行
中间件加工(压缩可能在此触发)→ 模型看到工具结果 → 这次不再发 tool_calls → 路由判否 → 触发 END → 没有任何节点再被触发 → tick 返回 false → 引擎收工

五 · deepagents 的零件在引擎里的安装位置

deepagents 概念(你已学过)在 langgraph 引擎里的真身
DeepAgentState 的 DeltaChannelmessages 通道的自定义 reducer(tick 第①步用它合并写入)
middleware 栈(五个检查站)被 langchain create_agent 织进 agent / tools 节点内部——引擎不知道中间件存在
checkpointer= 参数tick 第②步"每超步存档"的持久化后端;thread_id 是档案柜编号
interrupt / 人工审批引擎的 interrupt() 原语:暂停超步 + 持久化,恢复 = 同 thread 重新 invoke 带 Command(resume)
recursion_limit=9999引擎的超步步数上限(JS 版默认 25;deepagents 覆盖成 9999——findings 那条"几乎不设防")
task 子代理把一张编译图当作父图的一个节点(subgraph),checkpoint 命名空间以 | 分隔成树
一个诚实提醒:引擎自己不带任何安全与执行设施——无沙箱、无输出截断、工具以宿主进程全权限裸跑(审计:nd-exec-sandbox "设计上不提供")。所以 deepagents 替它装了权限和落盘,codex 全部自建——引擎越纯,框架越忙。
