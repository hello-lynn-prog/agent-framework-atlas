①总架构:单核多壳,一切汇入 core

四个客户端壳(TUI / exec / IDE / TS SDK)把请求交给 app-server(JSON-RPC),core 里每个线程一个 Session:任务外环套 run_turn 内环,工具调用先过护栏双链再进执行角色;模型是右侧独立的外部依赖,会话事实追加进左下的 rollout 日志。
core 控制层 执行角色 人/客户端壳 护栏门禁 存储留痕 外部模型

②总循环:任务外环 ⊃ run_turn 内环

外环负责任务级续跑判定(出错或没活干就收工);内环是真正的"采样→执行→回灌"心跳。用户在模型运行中插入的新输入进 steering 邮箱,下一 step 被自然消化——循环不被打断。

③一轮的生命周期状态机

从空闲收到 Op 开始,一轮 turn 在"采样↔工具"之间振荡,直到模型不再需要工具;stop hooks 可以放行、拦截续跑或强停;两个黄色状态是自愈路径,粉色是唯一的人工介入点。

④单轮端到端时序:一次 shell 调用的完整旅程

选最有代表性的一条链:用户输入 → 采样 → 模型要跑 shell 命令 → 过闸 → 沙箱执行 → 输出回灌 → 模型继续,直到不需要工具为止。底部的三个虚线盒是这条主链上的三个著名岔路。

⑤机制特写 1:审批双链 — 应用层策略 × 内核强制

Codex 护栏的独特处:应用层审批之下还垫了一层 OS 强制沙箱。静态规则引擎先行,能放行的免审批直接进沙箱;沙箱放不下的才升级人工;规则甚至可以改写命令(amend)而不是简单放行或拒绝。

⑥机制特写 2:code-mode — 把工具往返折叠成写代码

面对"N 个工具"的任务,Codex 提供了另一种范式:把工具目录编译成 TS 类型签名,让模型直接写一段 JS 在 V8 里一次跑完。N 次循环往返变 1 次,这是它和"每次一工具"框架最大的分野。
